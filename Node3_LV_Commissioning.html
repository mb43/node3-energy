⛔ ARCHITECTURAL ERROR IN THIS DOCUMENT — DO NOT USE FOR WIRING — 15 Sep 2026

This commissioning guide was built on a wrong architecture. It shows the Raspberry Pi connecting via USB-CAN directly to the e-NV200 battery packs. That is not the DALA design.

The correct architecture is:
• LEAF battery BMS CAN → T-2CAN CAN-B (DALA firmware handles BMS comms)
• T-2CAN CAN-A → FoxESS BAT CAN port (DALA emulates HV2600 battery to inverter)
• Raspberry Pi → USB serial → T-2CAN (DALA config/monitoring only)
• Raspberry Pi → RS485/USB → FoxESS COM port (Modbus for energy dispatch control)
• T-2CAN GPIO 21 → SSR-04 Ch1 → precharge coil
• T-2CAN GPIO 17 → SSR-04 Ch2 → negative contactor coil
• T-2CAN GPIO 48 → SSR-04 Ch3 → positive contactor coil

Diagrams 1 and 3 in this document are wrong. The step-by-step phases for RS485/Modbus (Phase 2) and CT clamp (Phase 4) remain valid. Use Node3_Wiring_Overlay.html for the corrected LV wiring reference.

Step-by-Step Commissioning Sequence

⚡ Phase 1 — Pi Boot and Connectivity
1
Connect 5V PSU to Pi — dedicated supply only Use an isolated 5V 3A PSU (DIN rail type recommended). Do NOT use the FoxESS USB output — inverter USB is noisy and may cause brownouts. Connect USB-C (Pi 4/5) or micro-USB (Pi 3).
2
Boot and find Pi on the network
ping raspberrypi.local # or use your router DHCP table ssh pi@raspberrypi.local # default pass: raspberry (change immediately)
3
Update OS and install dependencies
sudo apt update && sudo apt upgrade -y sudo apt install -y python3-pip python3-serial can-utils pip3 install minimalmodbus pyserial python-can
4
Enable SPI and configure overlays (if using MCP2515 CAN HAT)
sudo raspi-config # → Interface Options → SPI → Enable # Then edit /boot/config.txt and add: # dtoverlay=mcp2515-can0,oscillator=8000000,interrupt=25 # dtoverlay=spi-bcm2835
If using USB-CAN adapter (CANable/PCAN): skip this — it auto-appears as can0 via slcand.
⚡ Phase 2 — RS485/Modbus to FoxESS Inverter
5
Plug in USB-RS485 adapter — identify the device
ls /dev/ttyUSB* # Should show /dev/ttyUSB0 (first adapter) # If two adapters: RS485 = ttyUSB0, USB-CAN = different
6
Wire RS485 A/B to FoxESS COM port With inverter powered off: connect RS485-A (Yellow) to COM pin 1, RS485-B (Blue) to COM pin 2, GND to pin 3. If this is the only device on the Modbus bus, fit a 120Ω resistor across A and B at the adapter end.
7
Power inverter, test Modbus read
python3 << 'EOF' import minimalmodbus inst = minimalmodbus.Instrument('/dev/ttyUSB0', 1) # address 1 inst.serial.baudrate = 9600 inst.serial.parity = 'N' inst.serial.stopbits = 1 inst.mode = minimalmodbus.MODE_RTU # Read grid power register (Fox H3 register 0x0006 = grid power, signed int) val = inst.read_register(6, 0, 4, signed=True) print(f"Grid power: {val} W") # +ve = import, -ve = export EOF
✓ If you get a number (even 0W) — Modbus is working. If TimeoutError: check baud rate, slave address, and A/B polarity (swap if needed).
8
Key FoxESS KH10.5 Modbus registers to verify
Register (hex)DescriptionUnitsNotes
0x0006Grid powerW (signed)+ve = import, −ve = export
0x0010Battery SOC%0–100
0x000BBattery charge/dischargeW (signed)+ve = charging
0x0020Inverter temperature°C × 10divide by 10
0x001CPV powerW0 if no PV
⚠ Register map varies slightly between FoxESS firmware versions. Cross-check against your inverter's Modbus register table in the Fox ESS Open API documentation or the community register list.
⚡ Phase 3 — CAN Bus to e-NV200 BMS
9
Locate the e-NV200 BMS CAN connector The low-voltage BMS service connector is on the upper face of the battery pack (not the orange HV connector). It's a multi-pin automotive connector. Identify CAN-H and CAN-L using a multimeter in voltage mode: CAN-H ≈ 2.5–3.5V, CAN-L ≈ 1.5–2.5V during BMS activity.
⛔ HV must be isolated before working within arm's reach of the pack. LV connector only — orange = HV = hands off.
10
Wire CAN-H/CAN-L from master pack to USB-CAN adapter Use twisted pair (Cat5 works). Fit 120Ω across CAN-H/L at the pack connector end. Fit 120Ω at the USB-CAN adapter end. CAN-H = Red/Yellow wire, CAN-L = Blue/White wire (label clearly).
11
Bring up CAN interface and confirm traffic
# USB-CAN adapter (CANable/slcan method): sudo slcand -o -c -f -s6 /dev/ttyACM0 can0 sudo ip link set can0 up type can bitrate 500000 # OR if using MCP2515 HAT: sudo ip link set can0 up type can bitrate 500000 # Check for traffic: candump can0 | head -20 # You should see e-NV200 BMS frames (IDs in range 0x100–0x7FF)
✓ BMS actively broadcasts: SOC, cell voltages, temperatures, current, fault codes. Typical IDs: 0x355 (SOC/SOH), 0x356 (voltage/current/temp), 0x35A (alarms).
12
Decode BMS data — key CAN IDs for e-NV200
python3 << 'EOF' import can bus = can.interface.Bus(channel='can0', interface='socketcan') for msg in bus: if msg.arbitration_id == 0x355: soc = int.from_bytes(msg.data[0:2], 'little') / 10 print(f"SOC: {soc:.1f}%") elif msg.arbitration_id == 0x356: volts = int.from_bytes(msg.data[0:2], 'little', signed=True) / 100 amps = int.from_bytes(msg.data[2:4], 'little', signed=True) / 10 temp = int.from_bytes(msg.data[4:6], 'little', signed=True) / 10 print(f"V: {volts:.2f}V A: {amps:.1f}A T: {temp:.1f}°C") if msg.arbitration_id > 0x400: break EOF
⚠ CAN IDs and byte ordering vary between e-NV200 model year (2014 vs 2018+). Sniff with candump -l can0 to log a session, then decode empirically if values look wrong.
⚡ Phase 4 — CT Clamp (G99 Export Limiting)
13
Isolate at main incomer before any CT work Switch OFF the main isolator in the consumer unit. Verify dead with a voltage tester on L1/N at the terminals. The CT clamp is clip-on (non-contact) but the meter tails are still live unless you isolate. DO NOT work on meter tails — contact your DNO if access is needed at the sealed meter head.
⛔ Main supply meter tails (between DNO meter and main switch) remain live even with main isolator OFF. Never touch or clip CT onto these without DNO authorisation or an approved isolator upstream.
14
Clip CT around L1 only — after the DNO meter, before the main switch Open the CT clamp jaws, clip around the L1 (brown) conductor. The arrow/mark on the CT faces toward the load (away from the grid). Route the CT signal cable to the FoxESS meter input terminals.
15
Connect CT output to FoxESS S1/S2 terminals Use screened 2-core cable. Connect S1 and S2 to the FoxESS meter input. Connect the cable screen at the FoxESS end only (one-end grounding prevents ground loops).
16
Set export limit in FoxESS settings Power up, navigate to: Settings → Grid Settings → Export Limit
Set to 5500 W (your G99 conditioned limit per FJJ907/1).
✓ FoxESS uses CT reading to throttle battery discharge/AC export in real time. If CT is reversed (reads negative), swap S1↔S2 at the FoxESS terminals (do not re-clip CT).
⚡ Phase 5 — Software Verification
17
Run full connectivity check — confirm all three data paths
# Check RS485 Modbus (FoxESS inverter) python3 -c " import minimalmodbus i = minimalmodbus.Instrument('/dev/ttyUSB0', 1) i.serial.baudrate = 9600; i.mode = minimalmodbus.MODE_RTU print('SOC:', i.read_register(0x10, 0, 4), '%') print('Grid:', i.read_register(0x06, 0, 4, signed=True), 'W') " # Check CAN bus (BMS) candump can0 -n 5 # 5 frames, should show BMS data immediately # Check export limit is active # Watch grid register — discharge battery while reading grid power # It should self-limit to ≤ 5500W export
18
Verify Dovecote node3 server sees the hardware
# On Pi (or server), check node3 bridge is picking up inverter data: curl http://localhost:8585/api/status | python3 -m json.tool # Should return real SOC, grid_power, battery_power — NOT simulated values # "source": "hardware" ← look for this
⚠ The 19 Aug bug sweep found the dashboard JS fallback simulation was hiding behind a tiny label — if you see perfect curves instead of real jagged data, check the source field in /api/status.
19
Log a test discharge cycle and verify export cap Command a discharge to grid via Modbus or FoxESS app. Watch grid_power on the dashboard. Export should clamp at 5.5kW. If it exceeds this, re-check CT orientation and the FoxESS export limit setting.
20
Record commissioning data for G99 / DNO sign-off Note: inverter serial number, firmware version, CT type and installation point, measured export at cap, BMS serial and SOC at test. Your HV electrician will need this for the witness test documentation.

Pre-HV-Electrician Sign-Off Checklist

Complete all of the following before calling in the HV electrician for G99 witness testing:

LV Control Layer

  • Pi boots, SSH accessible, OS up to date
  • USB-RS485 identified at /dev/ttyUSB0
  • Modbus read of FoxESS SOC returns real value
  • Modbus read of grid power returns real value
  • USB-CAN interface can0 is up
  • candump can0 shows live BMS frames
  • SOC decoded from CAN matches inverter display
  • BMS temperatures reading (no sensor faults)
  • CT clamp installed on L1, after meter, pre-isolator
  • CT signal wired to FoxESS S1/S2
  • Screen earthed at FoxESS end only
  • Export limit set to 5,500W in FoxESS settings
  • Export cap verified under discharge test

Software / Monitoring

  • node3 server returning "source: hardware" not simulated
  • G99 5.5kW cap active and confirmed in live test
  • Dashboard at dovecoteltd.co.uk:8585 showing real data
  • LP dispatch running (not greedy fallback)
  • Battery SOC logging to database
  • Inverter temperature within spec (≤70°C)
  • No BMS fault codes in CAN frames (0x35A = 0)
  • Export data being logged for G99 compliance records
  • Engage/aggregator notified of commissioning date
  • FoxESS WiFi connected and reporting to FoxCloud (optional but useful)
  • Inverter serial + firmware version recorded
  • All wiring labelled and cable-managed
  • Commissioning log started with today's date
⛔ Do not energise the HV DC bus without your G99-qualified electrician present. The HV side (FoxESS ↔ e-NV200 pack strings) requires isolation verification, continuity checks, and insulation resistance testing before first energisation. LV commissioning above is preparatory only.
